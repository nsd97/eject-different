# Eject Different: guide for agents and contributors

A macOS app (Swift 6, SwiftUI, macOS 15+) whose one executable is also its own root launch daemon. Knock three times on an Apple silicon MacBook, and every unpluggable disk ejects. A success chord or Sosumi says how it went. The reasons behind each decision live as comments next to the code; this file is the map and the rules.

## Map

| Path | What it is |
|---|---|
| `EjectDifferent/main.swift` | Entry point with three modes: the app (no arguments), `--daemon`, and `--list`. Also the daemon's wiring: keep-awake, then sensor → detector → eject → chime, one log line per impact, and the notify(3) posts the monitor listens for. |
| `EjectDifferent/App.swift` | The one window. Turns the daemon on and off through `SMAppService`. |
| `EjectDifferent/Knock.swift` | The SPU accelerometer (IOKit HID) and `KnockDetector`: a 40 Hz high-pass (Accelerate's biquad), one count per impact, the three-knock rhythm, and an event for every impact, counted or not. |
| `EjectDifferent/Monitor.swift` | Debug builds only. A live chart of what the detector hears, the recorder that makes labeled sessions, and `Recording`, the label format the tests read. |
| `EjectDifferent/Eject.swift` | Which disks qualify, the eject loop, and the Time Machine exception. |
| `EjectDifferent/Chime.swift` | The volume and mute override, and playback. |
| `EjectDifferent/different.wav` | The success chord, generated by `Scripts/generate-success-chord.py`. |
| `LaunchDaemons/com.nsd97.EjectDifferent.daemon.plist` | The daemon's launchd plist. The "Embed Launch Daemon" build phase copies it to `Contents/Library/LaunchDaemons`. It sits outside the synchronized `EjectDifferent/` folder so it never lands in Resources. |
| `Evaluation/` | The labeled recordings the detector is scored against. See Evaluation below. |
| `EjectDifferentTests/` | Swift Testing. Scores the detector on `Evaluation/`; checks the rhythm rules on synthetic knocks, the recorder's files, report parsing, the disk rule, and the Time Machine rule. |

## Invariants

- **Never eject the internal disk, a disk image, or a network share.** Disk images report removable, external and ejectable. The "Virtual Interface" protocol check is the only thing keeping Xcode's simulator runtimes mounted.
- **Only Time Machine may be forced.** A disk held by `backupd` gets a stopped backup and, after `Eject.timeMachineGrace`, `diskutil eject force`. Any other holder means a refusal.
- **Never write power settings.** No `pmset`, no `SleepDisabled`. Staying awake is `caffeinate -s`, which applies only on AC and is a child of the daemon, so it dies with it. Answering a knock also declares momentary user activity (`IOPMAssertionDeclareUserActivity`, in `Chime.wake()`) to pull the Mac out of DarkWake into a full wake, so the chime is audible through a closed lid. That sets nothing and holds nothing; the Mac sleeps again on its own. Without it the eject still happens, but the sound is only heard on the next wake.
- **Full volume only on the built-in speakers.** Always restore volume and mute exactly.
- **The app does nothing at launch.** Only the button registers the daemon. Tests are hosted by the app, so this keeps them inert.
- **App Sandbox stays off.** The daemon is the same binary, and the sandbox would block IOKit, Disk Arbitration and the command-line tools.
- **`KnockDetector`'s constants are measured, not guessed.** Change them only by the Evaluation rules below, and keep `corpus()` passing. A Mac on a lap moves constantly, so never trigger on slow motion or on the gyroscope; that is what made the first version fire on its own.
- **The monitor and recorder are Debug only** (`#if DEBUG`). The shipping window stays one sentence and one button.

## Build and test

```bash
xcodebuild -project EjectDifferent.xcodeproj -scheme EjectDifferent -destination 'platform=macOS,arch=arm64' test

# Install where SMAppService expects it. Release ships; Debug adds the monitor.
CONFIGURATION=Release
osascript -e 'quit app "Eject Different"'
xcodebuild -project EjectDifferent.xcodeproj -scheme EjectDifferent -configuration $CONFIGURATION -derivedDataPath build build
rm -rf "/Applications/Eject Different.app" && ditto "build/Build/Products/$CONFIGURATION/Eject Different.app" "/Applications/Eject Different.app"
LSREGISTER=/System/Library/Frameworks/CoreServices.framework/Frameworks/LaunchServices.framework/Support/lsregister
find build ~/Library/Developer/Xcode/DerivedData -name "Eject Different.app" -prune -exec "$LSREGISTER" -u {} \; 2>/dev/null
"$LSREGISTER" -f "/Applications/Eject Different.app"
sudo launchctl kickstart -k system/com.nsd97.EjectDifferent.daemon   # run the new binary

# Release leaves the monitor out: this prints 0.
strings "build/Build/Products/Release/Eject Different.app/Contents/MacOS/Eject Different" | grep -c "to see the sensor"
```

Register the daemon only from `/Applications`, never from DerivedData. launchd doesn't remember where the app was: it finds the daemon's executable through Launch Services by bundle ID (`launchctl print` shows "resolve program"). Any registered build copy can win, Debug ones included, so unregister build products before restarting the daemon, as above.

Replace the installed app rather than copying over it: a Debug build carries `Eject Different.debug.dylib` and `__preview.dylib`, and a leftover one breaks the bundle's signature. Quit the app with `osascript`, not `pkill -x "Eject Different"`, which also matches the daemon.

## Evaluation

`Evaluation/` holds every labeled session, as a pair of files:

- `<scenario>-<date>.bin`: the readings. x, y and z for each, as little-endian Int16 in 1/16384 g.
- `<scenario>-<date>.json`: a `Recording` (in `Monitor.swift`). It names the Mac, the measured spacing between readings, and the split. Its segments run back to back, and each gives the prompt that was on screen and what it should produce: `triple`, `single` or `none`.

Record new sessions in a Debug build, under the chart: Lap, Desk and Moving are guided, and Everyday is one long `none` segment, until Stop. Each lands in `~/Library/Application Support/Eject Different/Recordings/`; copy both files into `Evaluation/`.

`corpus()` replays every recording through the daemon's own code. It fails when a `triple` segment doesn't fire exactly once, or any other segment fires at all. Its scorecard also finds the range of triggers that would still pass, by replaying, because the rhythm rules are what turn away a hard shove:

```
Knock evaluation · trigger 0.041 g
recording                 split    triples  false  singles  weakest knock  loudest other
lap-2026-10-08            tuning   3/3      0      3/3      0.054 g        0.155 g
tuning: works from below 0.010 to 0.052 g · 0 false triples in 0.7 min without knocking
holdout: no recordings yet
gaps between knocks in triples: 0.27–0.36 s (allowed 0.10–0.60 s)
```

xcodebuild doesn't show the output of tests the app hosts, so the scorecard is attached to the result instead:

```bash
rm -rf build/eval.xcresult build/eval
xcodebuild -project EjectDifferent.xcodeproj -scheme EjectDifferent -destination 'platform=macOS,arch=arm64' -resultBundlePath build/eval.xcresult test
xcrun xcresulttool export attachments --path build/eval.xcresult --output-path build/eval && cat build/eval/*.txt
```

The rules that keep it honest:

- Tune only on `tuning` recordings.
- New recordings arrive as `holdout`. Read the scorecard before touching any constant.
- A holdout you tuned on becomes `tuning`, and a fresh holdout replaces it.

The corpus lives in Git. An hour of Everyday is about 17 MB; move it to Git LFS once the folder passes about 200 MB.

## Hardware checklist

Run this after any change to sensing, ejecting, sound, or power.

1. `--list` prints nothing when only disk images are mounted.
2. Turn On and approve. `sudo launchctl print system/com.nsd97.EjectDifferent.daemon` shows it running as root, and a single knock logs `Knock 1` (see Logs below). In a Debug build, three knocks put 1, 2 and 3 on the chart, then the listener's ⏏ line.
3. Speakers at 30% and muted, knock three triples a few seconds apart with nothing attached: three loud Sosumis, then 30% and muted again. With headphones, they play at their current volume.
4. A USB stick and an SD card: `--list` shows them; knock; the chord plays; `diskutil list external` is empty; the simulator runtimes are still mounted.
5. Keep the stick in use (`cd` into it from a shell), then knock: Sosumi, and the log names the process.
6. On AC with the lid closed, a knock is still heard (`pmset -g log` shows DarkWake). On battery the Mac sleeps.
7. Sleep, wake, knock.

Logs: `log stream --predicate 'subsystem == "com.nsd97.EjectDifferent"'` (from a script, `/usr/bin/log`, because zsh has a `log` builtin). Each impact gets one line once it stops ringing, such as `Knock 2: peak 0.072 g` or `Not counted, too soon after the last impact: peak 0.031 g`. They're notice level, so `log show` still has them later.

`notifyutil -w com.nsd97.EjectDifferent.triple -w com.nsd97.EjectDifferent.chimed` prints a line each time the daemon hears three knocks and each time a chime actually plays. The two counts should match.
